## 一、作業要做什麼：一個透過工具查資料庫來回答的客服 Agent

選一家**店或一個單位**，為它做一個 **AI 文字客服 Agent**，並做出客人可以使用的對話畫面。

你的客服要和 **G-3 單元（客服 Agent）**的課堂範例一樣運作：客人的每個問題都先交給 Agent，由 Agent 決定要呼叫哪一個**工具**。工具負責查你的 **SQLite 資料庫**，或用程式做計算。模型不可以憑記憶回答。

![你要做出來的東西：你自己的客服 Agent](images/homework-architecture-zh.png)

對話畫面可以用以下任何一種方式開發：

| 方式 | 例子 | 說明 |
|---|---|---|
| **Gradio**（建議） | 從 G-3 單元的 `app-gradio.py` 改起 | 上課使用的工具，做得最快 |
| **其他網頁框架** | Streamlit；Django；Flask 或 FastAPI 後端，搭配 HTML 與 JavaScript 前端；React、Vue 或 Next.js | 用你熟悉或想學的框架 |
| **手機 App**（有興趣再挑戰） | React Native、Flutter、Android（Kotlin）或 iOS（Swift） | 額外的挑戰，用手機或模擬器的截圖即可 |

三種方式的基本要求（第三節）都相同，評分標準也相同。

> **後端的東西都放在伺服器端**：如果你做的是網頁前端或手機 App，**API 金鑰、Agent 迴圈、工具和資料庫都要放在後端**（伺服器程式）。**絕對不要把 API 金鑰寫在前端或 App 的程式碼裡**，任何人打開你的網頁或 App 都看得到。前端只負責把客人的訊息送到後端，再把回答顯示出來。

可以參考的題材：餐廳、咖啡店、書店、健身房、飯店或民宿、補習班、診所掛號櫃台，或學校裡的某個辦公室。**不要直接交上課的速食店範例**，請設計你自己的店或單位。

> **必須和 AI 協作（cowork）**：這份作業要**和 AI 工具一起完成**，例如在終端機裡使用 Claude Code、Codex、Gemini CLI，在 VS Code 裡使用 GitHub Copilot（agent 模式），或使用網頁版的 ChatGPT、Claude、Gemini。用它來規劃資料表和工具、寫程式、除錯，以及測試你的 Agent。**成果仍然由你負責**：AI 寫的程式要看懂、要實際執行，Agent 的每個回答都要自己檢查。報告範本第九節要說明你怎麼和 AI 協作。不要把 API 金鑰貼進任何 AI 對話。

## 二、從課堂範例改起，把屬於店家的部分全部換成你自己的

你可以從 G-3 單元的 `app-gradio.py`、`shop_info.csv`、`menu.csv` 改起；講義 `1-Agent-Tool-Calling.ipynb` 一步一步說明了每個部分。**方法保留，屬於店家的部分全部換掉**：

| 課堂範例的部分 | 你要換成 |
|---|---|
| `shop_info.csv`（營業時間、地址、外送、停車……） | 你自己的資訊表：客人會問到的店家資訊 |
| `menu.csv`（品項、價格、是否供應） | 你自己的紀錄表：你的服務、房型、課程或商品 |
| 工具（`get_shop_info`、`search_menu`、`get_price`、`calculate_total`、`transfer_to_human`） | 符合你店家的工具，名稱、說明和程式都要自己寫。**計算工具一定要符合你的情境**，不能只是把點餐金額加起來 |
| System prompt（角色與規則） | 你自己的角色與規則 |
| 對話畫面上的範例問題 | 你的客人會問的問題 |

## 三、基本要求：每個人的客服 Agent 都要有的部分

### 1. SQLite 資料庫：至少兩張資料表，從你自己的 CSV 檔建立

1. **資訊表**：像課堂的 `shop_info`，一個主題一列，欄位是 `topic` 和 `content`，**至少 8 個主題**。請放進客人最常問的事，例如營業時間、地址、付款方式、外送或停車。客人一直在問的事，就應該放在這張表裡。
2. **紀錄表**：像課堂的 `menu`，一項服務、房型、課程或商品一列，**至少 15 筆**。每一筆至少要有名稱、一個數字（價格或費用），以及是否供應。不是每個單位都賣餐點，請用適合你的欄位。
3. 程式**啟動時從 CSV 檔建立資料表**（見 G-3 講義的 Step 3）。繳交的是 CSV 檔，不是 `.db` 檔。

### 2. 至少四個工具，每一類各一個

| 工具類型 | 課堂範例 | 你的店可以怎麼做 | 客人可能會問 |
|---|---|---|---|
| 查資訊 | `get_shop_info(topic)` | 診所的門診時間、健身房的規定 | 「附近有停車位嗎？」 |
| 查紀錄 | `search_menu`、`get_price` | 找課程、房型或商品，查有沒有空位或存貨 | 「星期五的瑜伽課滿了嗎？」 |
| 計算（由程式算） | `calculate_total(items)` | 晚數 × 房價、月費加學生優惠、運費 | 「雙人房住三晚多少錢？」 |
| 轉真人 | `transfer_to_human()` | 客訴，或資料無法回答的問題 | 「我要找經理。」 |

工具要遵守上課講過的四個原則：

- **回傳資料，不回傳句子**：句子由模型來寫。
- **查不到要明確說出來**：否則模型會自己編。
- **計算在工具裡做**：不要讓模型自己算錢。
- **工具只接收參數，不讓模型寫 SQL**：查詢由你的程式組成，模型只負責填入參數值。

### 3. 安全、而且看得見過程的 Agent 迴圈

- 迴圈最多呼叫模型 `max_steps` 次，避免模型卡住時無限迴圈。
- **只執行你自己寫的工具**：模型要求不存在的工具名稱時，迴圈要拒絕。
- 對話畫面要**顯示工具軌跡**：呼叫了哪個工具、傳了什麼參數、拿回什麼結果，像 `app-gradio.py` 右側的「Tools used」面板。報告裡的截圖必須看得到工具軌跡。

### 4. System prompt：一個角色加上四類規則

| 規則類型 | 作用 | 課堂範例 |
|---|---|---|
| 接地 | 只根據工具結果回答；查不到就說查不到 | 「Answer only from tool results. Never invent anything.」 |
| 範圍 | 只談這家店，婉拒其他話題 | 「Only talk about this shop.」 |
| 分派 | 什麼問題用哪個工具 | 「Shop questions -> get_shop_info.」 |
| 語言與格式 | 回答的方式 | 「Answer in the customer's language, in three sentences or less.」 |

### 5. 會記住對話的聊天畫面

每次提問都要連同**對話歷史**一起送出，畫面上要有**開場招呼語**和**範例問題**。

## 四、測試你的 Agent 會不會選對工具、會不會守住範圍

讓 Agent 回答很容易，**讓它選對工具、守住自己的工作範圍才是難的地方**。

1. **四類問題**，每一類至少問一題（見 G-3 講義的 Step 9）：

   | 類型 | 好的回答 |
   |---|---|
   | 資料裡有 | 用對工具，回答資料庫裡的正確數值 |
   | 需要計算 | 數字由計算工具算出，不是模型自己算 |
   | 資料裡沒有 | 說「我沒有這項資訊」並轉給真人，絕不編造 |
   | 不是客服的事 | 禮貌婉拒，把話題帶回店家 |

2. **工具選擇測試**，**至少 10 題**：每一題寫下你可以接受的工具，執行測試並報告準確率，做法同 G-3 講義的 Step 11。答錯的題目，要說明你改了什麼（通常是工具說明或規則），再測一次。

> **客人常問、資料裡卻沒有的事，要補進資料，而不是補進規則。** 課堂範例就是因為這樣，把外送和停車加進 `shop_info.csv`。

## 五、把你的客服 Agent 描述清楚：服務誰、為什麼適合他們

這部分沒有標準答案，我們希望你把自己的客服說清楚。可以參考這些問題：

- **服務對象是誰？** 例如新客人、會員、學生或病人。
- **他們在什麼時候、為了什麼來問？** 通常想知道什麼、想辦什麼事？
- **沒有你的客服時，他們現在怎麼得到答案？** 例如打電話、看網頁、排隊詢問。
- **和同類產品有什麼不同？** 例如 ChatGPT 這類通用聊天機器人、網站的常見問答頁、LINE 官方帳號的自動回覆。你的客服在什麼情境下比它們更合適？
- **它提供哪些問答和服務？** 列出來，並在問答情境展示裡呈現。

## 六、加分項目：讓你的 Agent 更實用的選做功能

有時間的話任選，並在報告裡說明你做了哪些。

| 功能 | 意思 | 參考哪裡 |
|---|---|---|
| 會修改資料的工具 | 例如 `make_booking`：Agent 先摘要內容，客人確認之後，你的程式才寫入資料庫 | 自己設計 |
| 中英文雙語 | 加一欄中文名稱（`name_zh`），並由程式決定回覆語言 | G-3 講義的 Step 4 和 Step 6 |
| 寬鬆的名稱比對 | 客人不必照資料庫的名稱打字也查得到，例如「large Coke」 | G-3 講義的 Step 6 |

程式碼**只能用 GitHub 繳交**，不接受壓縮檔。

如果你從來沒有用過 GitHub，請先讀作業主資料夾（上一層）裡 `(FYR) GitHub Guide and README Template` 子資料夾的 **`(FYR) GitHub-Guide-EN.md`**（英文，僅供參考）。它說明怎麼申請 GitHub 帳號、怎麼從自己的電腦把專案上傳，以及怎麼請 AI 工具幫你上傳。

專案裡要有這些檔案：

| 檔案 | 說明 |
|---|---|
| 你的程式碼 | Gradio：只要 Gradio app 本身，例如 `app.py`（或像 `app-gradio.py` 這樣的檔名），以及它會 import 的 Python 檔。其他框架或 App：前端與後端的所有原始碼資料夾 |

**只需要上傳 app**：用來試做或展示步驟的 Notebook（`.ipynb`）不用上傳。老師會直接執行你的 app，所以 app 和它的 CSV 檔本身必須是完整、可以執行的。

請遵守以下規定：

1. 專案要設成**公開（Public）**，老師才看得到。貼上連結前，請用瀏覽器的無痕視窗打開一次，確認不用登入也看得到。
2. **`.gitignore`** 的內容至少要有下面這幾行。`*.db` 讓資料庫檔不會被上傳，因為程式會從 CSV 檔重新建立它：

   ```text
   .env
   *.db
   __pycache__/
   venv/
   .venv/
   node_modules/
   build/
   dist/
   ```

3. 在 PDF 第一頁的基本資料裡填上**專案連結**。評分以截止時專案裡的版本為準，截止之後的修改不算。

**用範本寫 README.md**：GitHub 會把 `README.md` 顯示在專案首頁，這是老師打開專案時第一個讀到的內容。請把作業主資料夾（上一層）裡 `(FYR) GitHub Guide and README Template` 子資料夾的 **`(FYR) README-Template.md`** 複製到你的專案裡，改名成 `README.md`，再把每一節填好：客服做什麼、服務對象、工具和資料表、截圖，以及一步一步的安裝與執行方式。

> **金鑰安全**：`.env` 含有你的 API 金鑰，**不可以推上 GitHub**。公開在網路上的金鑰，幾小時內就可能被別人掃到並盜用。如果不小心上傳了，請立刻刪除那把金鑰、重新申請一把；**只把檔案從 GitHub 刪掉是不夠的**，因為 git 的歷史紀錄裡還查得到。專案裡含有金鑰的，會酌予扣分。

> **API 的注意事項**：API 設定放在 `.env` 檔：把 `.env.example` 複製成 `.env`，再填上 `API_KEY`。工具呼叫需要支援 `tools` 參數的端點和模型，G-3 講義的 Step 1 會先檢查。出現 429 錯誤表示呼叫太頻繁：免費方案可能每分鐘只能呼叫約 15 次，而一個需要工具的問題至少要呼叫兩次，所以測試題之間請加上 `time.sleep()`。
